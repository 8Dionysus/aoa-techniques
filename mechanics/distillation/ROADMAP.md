# Distillation Roadmap

This roadmap names Distillation future pressure for `aoa-techniques`. It is not
a donor ledger, migration ledger, source archive, generated verdict, or
technique-status surface.

Use it to choose the next distillation move. Use `LANDING_LOG.md`,
`PROVENANCE.md`, part-local reviews, and `legacy/` when the question is what
already landed and where its source evidence lives.

## Next Work

1. Keep the atom, topology, source-law, local-form, and bridge gates enforced in
   donor refinery, external import, candidate-ledger reopen rules, and any new
   reform ingress.
2. Start the next reform program with a corpus-wide bundle anatomy and
   small-agent usability audit before changing individual leaves.
3. Use the Technique Reform Ingress packet for any broad classification or tree
   pressure, but move one bounded slice at a time.
4. Use the Agon candidate handoff lane only for one candidate family at a time,
   and only after the candidate can name atomic move, topology, portability,
   owner stop-lines, nearest overlaps, examples, and validation.
5. Keep external, cross-layer, Agon, and recurrence registries paired with their
   active READMEs and generated indexes. Registries are accounting evidence, not
   candidate authority.
6. Before compacting another candidate ledger, record its exact pre-change Git
   commit and original path in `PROVENANCE.md` or the retirement decision, then
   update `LANDING_LOG.md`; do not create an archive-only raw copy.

## When Time Comes

- Add a new Distillation part only when repeated practice no longer fits donor
  refinery, external import, candidate ledgers, Agon handoff, technique reform
  ingress, or long-gap re-entry.
- Promote a distillation-shaped practice into `techniques/` only when it is one
  atomic import, narrowing, handoff, or re-entry move with stable inputs,
  outputs, risks, examples, and validation.
- Add a generated distillation summary only if repeated agent work needs the
  same lookup shape across several parts.
- Route proof, memory, routing, runtime, playbook, role, KAG, stats, release,
  and sibling-owner authority to the owning repo instead of localizing it here.

## Out Of Scope

- Flattening all donor material at once.
- Treating donor-specific doctrine as higher law for `aoa-techniques`.
- Treating generated registries, scouts, projections, or parity reports as
  source truth.
- Changing technique status from distillation pressure alone.
- Turning `ROADMAP.md` back into a migration ledger, raw source dump, or hidden
  backlog.
- Importing AoA center law, sibling owner acceptance, proof verdicts, memory
  canon, runtime activation, route dispatch, stats truth, or playbook
  choreography into this package.
