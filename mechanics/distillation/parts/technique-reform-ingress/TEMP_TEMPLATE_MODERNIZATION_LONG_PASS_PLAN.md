# Temporary Template Modernization Long-Pass Plan

Source packet: [Technique Reform Ingress](README.md)

Status: superseded temporary rhythm plan. The durable closeout is
[Template Modernization Long-Pass Closeout Ledger](reviews/template-modernization-long-pass-closeout-ledger.md).

This file replaces the too-small first expansion framing. The long pass is one
continuous corpus pass with internal shelves and phases for reviewability. The
internal phases are not separate doctrine, not a schema plan, and not an excuse
to stop after the first comfortable cohort.

This file is not bundle authority, not a roadmap, not schema truth, not
frontmatter migration authority, not generated output, and not empirical
small-agent proof.

## Purpose

Carry template modernization from the `proof/skill-support` pilot through the
full current technique corpus.

The pass asks one question across the whole tree:

Can each technique be made easier to use as a compact
`pick -> inspect -> execute` atom by adding the approved optional source
sections only when direct evidence shows the current shape hides the atom,
input packet, output shape, or stop-line?

The approved optional sections are:

- `Atomic move`
- `Topology fit`
- `Small-agent execution shape`

The pass should not rewrite every bundle for symmetry. It should review every
bundle, repair source where the repair is real, hold where the existing source
is already sufficient, and leave a durable closeout ledger with no hidden tails.

## Stop Lines

Do not turn template modernization into:

- a full-corpus cosmetic rewrite
- a required-section migration
- a new frontmatter axis
- a tree/path migration
- a relation migration
- an eval harness or pass/fail verdict
- a skill workflow import
- an AoA constitutional bridge block
- a generated-catalog hand edit
- a local small-model proof claim
- a sibling-owner policy surface

If direct reading exposes a real relation, owner-boundary, portability,
promotion, or eval problem, record it as `route-to-other-lane` in the current
review packet and keep the template-modernization pass moving.

## Repair Gate

Accept source-shape repair only when all of these are true:

1. The bundle's executable center is present.
2. The current source shape makes the atomic move, input packet, output shape,
   or stop-line harder to extract than the modern optional-section shape.
3. The proposed `Atomic move` is one action, not a skill workflow, playbook, or
   product process.
4. The proposed `Topology fit` clarifies current tree placement without turning
   scout axes into frontmatter truth.
5. The proposed `Small-agent execution shape` names context packet, expected
   output, and visible stop-line.
6. The repair preserves frontmatter, status, paths, relations, checklist,
   example, and notes unless a separate direct-repair decision exists.
7. The new text is shorter and clearer than a general explanation block.

Hold without source repair when:

- the current source is already easy to execute once selected
- the edit would add only template symmetry
- the bundle needs another lane before source-shape repair is honest
- the small-agent section would overclaim selection, autonomy, or empirical
  model success
- the atom is intentionally obvious from existing headings and examples

## Per-Bundle Rhythm

Use this loop for every bundle, including holds:

1. Reopen this file and mark the active phase in `Live Notes`.
2. Read route cards:
   - `AGENTS.md`
   - `mechanics/AGENTS.md`
   - `mechanics/distillation/AGENTS.md`
   - `mechanics/distillation/parts/AGENTS.md`
   - `techniques/AGENTS.md`
   - nearest trunk `AGENTS.md`
3. Read direct bundle source:
   - `TECHNIQUE.md`
   - local checklist
   - local examples
   - `notes/adverse-effects-review.md` when present
   - `notes/second-context-adaptation.md`
   - `notes/origin-evidence.md` or external-origin notes when present
4. Read compact companions and prior evidence:
   - `docs/TECHNIQUE_CAPSULES.md`
   - `docs/TECHNIQUE_SECTIONS.md`
   - `reports/technique_topology_scout.md`
   - relevant migration, selector, portability, owner-boundary, bundle-anatomy,
     execution-profile, or generated-capsule packets
5. Write a working row:
   - current atom
   - input packet
   - output shape
   - stop-line
   - repair verdict: `repair`, `hold`, or `route-to-other-lane`
   - evidence reference
6. If repairing, add only the three optional sections in fixed slots:
   - `Atomic move` after `Intent`
   - `Topology fit` after `Atomic move`
   - `Small-agent execution shape` after `Core procedure`
7. Rebuild generated surfaces through scripts only.
8. Write or update the current phase review packet.
9. Validate before moving to the next phase.
10. Land completed phases when the user asks for commit, push, and merge.
