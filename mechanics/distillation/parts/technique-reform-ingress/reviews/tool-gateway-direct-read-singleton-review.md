## Verdict

Accept `tool-use/tool-gateway` as the twenty-eighth bounded migration pilot
over the singleton `AOA-T-0065 mcp-gateway-proxy`.

The earlier singleton hold was correct while larger split pressure remained.
After the automation-governance split tail closed, direct reading shows that
keeping the last broad `agent-workflows` bundle in place now hides the real
selection question. `AOA-T-0065` is not a generic workflow chain; it is one
tool-use composition move: front multiple configured MCP or tool providers
through one explicit gateway surface with visible metadata and mediated
sanitization.

The acceptance is narrow. It does not make a general MCP platform, API gateway
product, connector registry, tool marketplace, capability discovery policy,
security scanner, trust-scoring system, local service lifecycle, runtime
deployment owner, skill activation surface, route mutation, memory truth, KAG
promotion, ToS canon, or canonical technique promotion.

## Why This Singleton Holds

- The reusable object is singular by nature: one gateway proxy seam. Splitting
  it further would produce fake categories rather than smaller techniques.
- The support package is strong enough for path placement: external origin,
  external import review, second-context adaptation, canonical-readiness note,
  one checklist, and one minimal example are all present and public-safe.
- The remaining canonical-readiness gap is about default/canonical promotion,
  not about whether the current path hides the technique's browsing home.
- Moving the bundle under `tool-use/tool-gateway/` makes the future tree more
  honest without changing `domain`, `kind`, status, evidence, or relation
  metadata.
- The old `agent-workflows` domain can stop carrying a single tool-use proxy
  representative after the migration lands.

## Watch Signals

- The gateway can drift into MCP platform ownership if dashboards, tenancy, or
  broader product packaging become the center of the technique.
- The gateway can drift into security-scanner or trust-scoring doctrine if
  source preflight replaces runtime proxy mediation.
- The gateway can drift into capability registry work if publication-time
  discovery becomes more important than the caller-facing proxy seam.
- The gateway can drift into runtime lifecycle ownership if startup and
  shutdown mechanics dominate the technique.
- `AOA-T-0065` remains promoted; the live-adopter gap in canonical readiness
  still blocks canonical promotion.
