This wave closes the last main owner-boundary coverage band: knowledge-lift,
media ingest, history artifacts, and tool gateway. These shelves are useful
because they are concrete, but each one sits beside a larger owner that could
swallow the technique atom: KAG can become graph truth, ingest can become a

gateway can become MCP platform, marketplace, scanner, or runtime law.

parser, moderation, auth, memory, or cleanup automation. `history/history-
artifacts` owns saved and derived reviewable history artifacts, not memory

authority. `tool-use/tool-gateway` owns one proxy mediation seam, not runtime
lifecycle, registry publication, marketplace curation, scanner products, trust
scoring, or connector ownership.

derived or intermediary status visible.

The local atom may lift sections, metadata, notes, relations, caution,
repo-docs, templates, review clusters, OCR handoffs, post-OCR fields,
duplicate groups, media buckets, Telegram normalized objects, saved sessions,
transcript packages, local indexes, witness traces, replay artifacts, code

KAG graph semantics, retrieval policy, media cleanup, connector auth, memory
writeback, retention policy, instruction authority, hosted product behavior,
tool marketplace governance, security scoring, runtime lifecycle, or eval
proof.

Adjacent split:

- `aoa-kag` owns graph or retrieval substrate meaning; source-lift techniques
  only create bounded derived reader surfaces that route back to source.
- `aoa-memo` owns memory objects, recall truth, temporal relevance, and
  writeback semantics.
- `aoa-routing` owns route products and dispatch hints; ingest buckets and
  source-lift readers are inputs, not routing law.
- `aoa-evals` owns proof verdicts, empirical reports, and pass/fail authority.
- `aoa-playbooks` owns scenario composition and recurring choreography.
- `aoa-skills` owns accepted executable workflows, skill packages, triggers,
  activation, and command behavior.
- runtime and connector owners own services, deployment, auth/session
  handling, local host behavior, API products, and tool-provider operations.
- local project owners own deletion, archive, retention, sharing, adoption,
  approval, and execution.

## Wave Findings

`knowledge-lift/kag-source-lift` holds because each leaf names the authored
source object first. Markdown sections, frontmatter, notes, relations, risks,
repo docs, GitHub templates, and semantic-review docs may be lifted into
derived lookup surfaces, but meaning stays in the authored surface. KAG wording
is family pressure and provenance, not `aoa-kag` ownership.

`ingest/media-ingest` holds because all five leaves stop at reviewable
intermediate objects. OCR handoff is not field parsing; field extraction
requires the OCR handoff but stays smaller than bookkeeping; dedupe groups do
not delete; semantic buckets do not moderate or route; Telegram normalization
does not own auth, sessions, live control, or memory.

`history/history-artifacts` holds because artifacts remain history, not
memory. Capture, transcript packaging, local indexing, witness trace, replay,
and code lineage all preserve reviewability while refusing instruction policy,
retention doctrine, memory substrate, repo analytics, hosted products, and
proof authority.

`tool-use/tool-gateway` holds because `AOA-T-0065` is a single proxy seam.
It fronts configured upstream tools through visible metadata and mediation,
while lifecycle, scanning, reputation, registry, marketplace, tenancy, product
packaging, and deployment stay outside.
