# Release Support Direction

Release-support in `aoa-techniques` keeps release-shaped practice portable
without pretending that practice notes approve a release.

This file owns the local direction only. AoA center owns release-support state
transition law, public support posture, owner split, and owner-request grammar.

## Source-of-truth Split

- `README.md`: package entry card and shortest route.
- `DIRECTION.md`: current local direction.
- `PARTS.md`: active part map.
- `parts/`: concise local mechanics surfaces.
- `PROVENANCE.md`: bridge from pre-split flat files and center release-support
  pressure to active parts.
- `LANDING_LOG.md`: dated structural accounting.
- `ROADMAP.md`: future contour, not a historical ledger.

## Local Contour

This package can name:

- staged landing, migration safety, smoke gate, rollback, and replay-audit
  practice
- release ritual, decision sealing, rollback rehearsal, and post-release watch
  practice
- owner-local artifact flow before activation or denial
- release-shaped candidate pressure that is not yet technique canon

It cannot name:

- AoA release-support law or federation release protocol
- GitHub release truth or public release authority
- public claim support without proof
- operator substitution or consent
- sibling owner acceptance
- runtime deployment or rollback execution
- Tree-of-Sophia write authority
- automatic technique promotion

## Growth Rule

Add detail only when repeated release-support work needs a clearer route into
portable technique practice, owner-local handoff, or future bundle review.

If the output needs proof, public projection, routing, SDK compatibility,
derived summaries, runtime deployment, rollback execution, or owner acceptance,
route to the owner repository instead of expanding local prose.
