# Method-Growth Roadmap

This roadmap names Method-growth future pressure for `aoa-techniques`. It is
not a release commitment, source ledger, maturity score, or owner-acceptance
surface.

## Current Contour

Method-growth is the local route for adoption, handoff, retention,
obsolescence, and owner-aware landing pressure around reusable practice.

The first active extraction pass yielded four technique atoms while leaving the
broader lifecycle in mechanics. This is the desired local shape: extract one
compact move, preserve the larger route, and keep sibling owner authority
outside the bundle.

  Deletion, deprecation execution, proof, memory, skill, routing, runtime, and
  owner-local retirement authority remain outside the technique.

## Next Work

1. Keep the four extracted atoms tied back to their provenance and package
   parts without reopening broad lifecycle prose inside the bundles.
2. Reassess adoption lifecycle only when a repeated local route cannot fit
   `local-pattern-adoption-gate`, `adopted-practice-retention-review`, or
   `superseded-practice-obsolescence-route`.
3. Reassess handoff only when a second owner-facing skill proposal packet shows
   a stable field or validation shape not covered by AOA-T-0102.
4. If a future compaction needs historical source recovery, record the exact
   pre-change Git commit and original path in `PROVENANCE.md` or the retirement
   decision; do not create a `legacy/raw/` copy or archive-only ledger.

## When Time Comes

- Add an adoption evidence registry only if several local adoptions need the
  same source-backed lookup shape.
- Add a generated compatibility view only after the authored package parts and
  extracted bundles prove stable.
- Route skill acceptance, skill execution, trigger policy, runtime activation,
  proof verdicts, memory canon, and owner-local retirement to stronger owners.

## Out Of Scope

- Treating Method-growth as a backlog for every future technique change.
- Maturity scores or automatic promotion.
- Owner acceptance from local adoption evidence.
- Skill execution truth or skill activation.
- Proof, memory, routing, runtime, stats, playbook, or ToS authority.
