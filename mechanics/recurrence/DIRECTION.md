# Recurrence Direction

Recurrence in `aoa-techniques` keeps recurring signals around technique canon
reviewable without pretending that observation is authority.

This file owns the local direction only. AoA center owns recurrence law,
vocabulary, owner split, and owner-request grammar.

## Source-of-truth Split

- `README.md`: package entry card and shortest route.
- `DIRECTION.md`: current local direction.
- `PARTS.md`: active part map.
- `parts/`: concise local mechanics surfaces.
- `PROVENANCE.md`: bridge from pre-split flat files and center recurrence
  pressure to active parts.
- `LANDING_LOG.md`: dated structural accounting.
- `ROADMAP.md`: future contour, not a historical ledger.

## Local Contour

This package can name:

- which local producer signals may feed technique review
- which source surfaces remain decision routes
- which generated surfaces stay observation evidence only
- how recurrence-fed review decisions close without changing technique status

It cannot name:

- AoA recurrence law or global return doctrine
- runtime return, self-healing, or resume behavior
- memory recall or hidden continuity
- routing dispatch or re-entry legitimacy
- proof verdicts or recovery-quality claims
- playbook choreography or recurring scenario method
- SDK carry, graph closure, or mutation authority
- automatic candidate creation or technique promotion

## Growth Rule

Add detail only when repeated technique-layer recurrence signals need a clearer
route into intake review, overlap holds, canonical-pressure followthrough, or
decision closure.

If the output needs execution, proof, memory, routing, playbook choreography,
runtime activation, SDK carry, derived visibility, or source regrounding, route
to the owner repository instead of expanding local prose.
