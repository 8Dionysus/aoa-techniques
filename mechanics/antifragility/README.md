# Antifragility

This package owns the `aoa-techniques` side of the cross-project Antifragility
mechanic: portable stress, chaos, degraded-mode, regrounding, and recovery
practice around technique canon.

Antifragility here is thinner than the center mechanic in `Agents-of-Abyss`.
The center owns doctrine, via negativa, anti-authority posture, fragile-pattern
vocabulary, and owner-request packets. This repo owns reusable practice pressure
and technique-family bridges that may feed or explain technique bundles.

This package may point to those anchors. It does not promote, demote, or certify
them.

## Boundary

Antifragility can prepare and route reusable stress-recovery practice. It does
not define one-score health, deletion authority, owner-local cleanup authority,
proof verdicts, runtime self-healing, memory truth, stats meaning, playbook
choreography, or automatic technique promotion.

Stable reusable antifragility practices become technique canon only through the
normal `techniques/**/TECHNIQUE.md` review path.

## AoA relation

`Agents-of-Abyss` owns antifragility doctrine, active part topology, fragile
pattern routing, and current owner-request packets. The current center queue has
no direct `ORQ-ANTIFRAGILITY-TECHNIQUES-*` request, so local antifragility
pressure is recorded as candidate-only practice pressure in
[Owner Request Receipts](../REQUEST_RECEIPTS.md).
