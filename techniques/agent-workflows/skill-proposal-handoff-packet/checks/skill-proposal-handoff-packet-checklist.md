# skill-proposal-handoff-packet checklist

Use this checklist before sending a technique-side skill proposal to a receiving
skill owner.

- [ ] One reusable practice, technique, or technique candidate is named.
- [ ] One receiving skill owner or skill-owning surface is named.
- [ ] The execution pressure for skill packaging is explicit.
- [ ] The proposed trigger boundary is visible.
- [ ] Inputs, outputs, and workflow shape are sketched without becoming a skill body.
- [ ] Technique dependencies are referenced instead of copied or redefined.
- [ ] Risks, approval seams, rollback needs, and verification hints are visible.
- [ ] Nearest wrong owner targets or defer conditions are named.
- [ ] The packet states that it does not create, accept, or activate a skill.
- [ ] Proof, scenario, memory, runtime, and command concerns route away when they are the real owner problem.
