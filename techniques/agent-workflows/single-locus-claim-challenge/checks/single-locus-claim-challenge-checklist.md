# single-locus-claim-challenge checklist

Use this checklist before challenging a claim inside a bounded review.

- [ ] One target claim is named.
- [ ] Exactly one vulnerable locus is named inside the claim.
- [ ] The pressure reason explains why that locus is vulnerable.
- [ ] The next support question is concrete enough to answer, narrow, or defer.
- [ ] The stop condition says the challenge is not proof, verdict, or adjudication.
- [ ] The challenge does not target a person, team, repo, or worldview.
- [ ] The output does not ask for broad research.
- [ ] The output does not issue route, memory, runtime, skill, actor, rank, scar, KAG, ToS, eval, or Agon law effects.
