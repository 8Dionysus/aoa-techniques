# Adverse Effects Review

## Technique
- id: AOA-T-0075
- name: session-donor-harvest

## Review focus
- promotion from `promoted` to `canonical` after live cross-context reinforcement from `aoa-sdk` checkpoint closeout and supporting public LangSmith reviewed-run curation docs
- confirm that donor harvest remains one post-review extraction pass over a reviewed artifact, not checkpoint capture, transcript packaging, memory writeback, owner placement, quest promotion, or evaluation dataset curation

## Failure modes
- unreviewed live session notes are harvested as if they were reviewed artifacts
- candidate records describe broad topics instead of bounded reusable units
- evidence anchors are omitted, vague, or detached from the reviewed artifact
- one donor pack silently chooses final owner placement or promotion status
- hold and defer disappear, forcing weak residue into candidate records

## Negative effects
- over-harvesting can flood owner repos with thin candidates
- teams may treat a rich donor pack as proof that a technique, skill, quest, or memory object is already accepted
- reviewed session history can become instruction authority if the evidence role is not kept explicit
- checkpoint hints can be mistaken for final harvest output
- reusable-unit extraction can be confused with dataset curation, transcript indexing, or generic summarization

## Misuse patterns
- running donor harvest during an active session before review
- treating every repeated phrase or theme as a reusable unit
- turning the donor pack into an owner-routing graph, memory object, or promotion ledger
- using generated summaries as the primary source when the reviewed artifact is available
- omitting weak, deferred, or rejected material to make the session look cleaner than it was

## Detection signals
- candidate names are nouns or themes instead of executable or reusable units
- records lack evidence anchors back to reviewed artifacts
- the donor pack includes final owner acceptance, proof verdict, memory writeback, or quest promotion language
- checkpoint note fields appear as final harvest claims without a reread step
- reviewers cannot explain why a candidate was kept, split, deferred, or dropped

## Mitigations
- require one reviewed source artifact before any donor harvest pass
- split merged clusters until each kept record names one reusable unit
- preserve evidence anchors, owner hints, nearest wrong targets, and hold or defer outcomes as review aids, not final verdicts
- route owner placement, quest promotion, memory writeback, evaluation, and transcript indexing to sibling techniques or owner repos
- treat external reviewed-run curation systems as supporting analogy unless they preserve the donor-pack boundary directly

## Recommendation
- safe to promote as a canonical agent-workflow lift technique when the output remains a bounded donor pack rooted in reviewed evidence
- keep future revisions narrow: do not absorb checkpoint capture, closeout execution, transcript packaging, local indexing, owner placement, quest promotion, memory writeback, stats refresh, or evaluation dataset governance into this bundle
