# AOA-T-0054 Kind Remap

Date: 2026-05-04

## Status

Accepted.

## Context

`AOA-T-0054 compaction-resilient-skill-loading` was classified as `handoff`.
The second kind ambiguity review found that the audit's `handoff` vs `workflow`
frame was incomplete because the bundle repeatedly centers post-compaction
skill recovery.

The destination check compared `handoff`, `workflow`, and `recovery` using the
bundle, checklist, example, notes, registry definitions, and neighboring
handoff/recovery techniques.

## Decision

Remap `AOA-T-0054` from `handoff` to `recovery`.

Keep its `domain`, `status`, ID, evidence, relations, and promoted posture
unchanged. The change is a classification correction only.

## Alternatives

- Keep `handoff`.
  Rejected because the bundle does not define the transfer artifact,
  checkpoint packet, or episode boundary. It restores skill availability after
  compaction has weakened the normal capability context.
- Move to `workflow`.
  Rejected because the procedure exists to serve recovery. The main promise is
  not how to perform ordinary bounded work; it is how to keep skill capability
  discoverable after context loss.
- Add a new kind such as `compaction`.
  Rejected because the current registry already has a narrower honest fit:
  `recovery` covers degraded continuation and explicit recovery posture.

## Consequences

- Generated kind surfaces will list `AOA-T-0054` under `recovery`.
- `handoff` keeps the pre-compaction packet and continuation seams, especially
  `AOA-T-0057`.
- `AOA-T-0054` remains `promoted`; no canonical claim or status change is made.
- The technique still stays outside full context reconstruction, memory recall,
  marketplace discovery, and install behavior.
